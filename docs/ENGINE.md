# Устройство Story Engine

Визуальная новелла с историями DeepSeek: развилки, произвольное действие,
готовые фоны и персонажи, динамические эмоции, погода, музыка и сохранения.
Backend — FastAPI, интерфейс — React/Vite. Для новой генерации нужен свой ключ DeepSeek.

## Запуск

После локальной сборки `dist/StoryEngine.exe` запускается без установленного Python и Node.
Он открывает игру в браузере, сервер слушает только `127.0.0.1`.
Если порт 8756 занят, выбирается свободный; адрес напечатан в консоли.

Запуск исходников из корня проекта:

```powershell
python -m pip install -r requirements.txt
npm --prefix frontend ci
npm --prefix frontend run build
python backend/run.py
```

При первом запуске введите ключ в настройках. Он хранится в
`%USERPROFILE%/.story_engine/config.json`, не возвращается интерфейсу
и маскируется в журнале обращений. Настройки и снимки записываются атомарно.

Для разработки: сервер `python backend/run.py`, интерфейс
`npm --prefix frontend run dev` (порт 1420). Vite проксирует API и ассеты
на порт 8756; при разработке он должен быть свободен.

Меню создания истории, настройки и продолжение сохранения оформлены как
диалоговое окно: общие палитры, тонкая рамка и кнопки выбора.
При открытии приложения выбирается случайный фон с изменяемым освещением;
он сохраняется между шагами меню. Время устройства игрока определяет оттенок
фона и окон: 05–11 утро, 11–17 день, 17–22 вечер, 22–05 ночь. При смене времени
палитра плавно обновляется; запросы к DeepSeek для этого не нужны.
Завязку можно читать и редактировать в многострочном поле. Меню адаптировано
для телефона; счётчик сцен появляется после начала игры.

## Чтение и настройки

Продолжение: кнопка, Enter, Space или клик по свободной области. Нажатия на
кнопки/панели, ввод и выделение текста не перелистывают. На финале работают
только явные кнопки. Текст сцены выдаётся небольшими фрагментами, выбор — после
последнего. Шестерёнка сохраняет место чтения и содержит музыку, эмбиент,
громкость и размер текста (16–36 px, с предпросмотром). Эти настройки сохраняются
автоматически. Музыка продолжает играть в другой вкладке; мобильная ОС всё ещё
может приостановить браузер в фоне.

Новые сцены содержат последовательные блоки повествования, реплик и мыслей.
Имя говорящего показывается над репликой, цвет привязан к ID; мысли — курсивом.
Старые сцены читаются в прежнем виде, без повторной генерации. В блокноте есть
внешность встреченных персонажей, а панели следуют игровому времени суток.

Шестерёнка → «Логирование заглушек»: контекст, причины, количество случаев,
JSON-выгрузка. Нехватка подходящей графики отделена от ошибки файла/обработки.
Журнал `~/.story_engine/fallbacks.sqlite3` не дублирует повторное чтение узла.
Прежний журнал `missing_backgrounds.sqlite3` остаётся доступен через API.

## Генерация истории

Используется только `deepseek-flash` (V4.1 Flash); thinking отключён во всех запросах (`thinking: {type: disabled}`),
включая меню, персонажей, план, события, прозу и проверки. `reasoning_effort` не передаётся.
Жанры/тональности и уточнения выбираются в меню. Далее одним запросом
создаётся общий ориентир по сегментам, другим — весь каст и начальные отношения.
В запрос каста передаются все уточнения игрока, которые имеют приоритет над догадками.

Каст — 2–3 взрослых персонажа вместе с главным героем. Герой от первого лица
не рисуется: штатно одновременно видны до двух спрайтов. Отдельного числового
лимита спрайтов в промпте нет; модель получает фиксированный каст.
Уникальные ID `c1`, `c2`, … связывают действия, реплики и отношения;
отображаемые имена могут совпадать. Числовой возраст ниже 18 повышается до 18.

Общий план содержит только типы мест и крупные события. Детальный сегмент —
события до следующего выбора из двух вариантов или финала. Его планирование —
один запрос. Перед прозой посещаемый сегмент целиком проверяется одним
запросом по касту, исходным условиям и полному журналу выбранной ветки.
Проза пишется одним отдельным запросом; её проверки нет.
Перелистывание готовых сцен не вызывает модель.

- Обычный режим заранее готовит события двух ближайших продолжений и допускает
  своё действие. Глубокие ветки и непосещённая проза не генерируются.
- Экономичный режим готовит события продолжения только после выбора.
  Произвольное действие недоступно.

Для двух развилок штатное прохождение после меню — 13 запросов в обычном режиме
и 11 в экономичном (включая три проверки посещённых сегментов). Меню обычно добавляет три: предложения затравок, жанр/тон,
уточнения. Повторы при сетевых/форматных ошибках увеличивают это количество.
Цена определяется фактическими токенами, а не числом обращений.

Своё действие проверяется одним запросом вместе с планированием последствий.
Если оно неприемлемо, возвращаются вопрос и три близких допустимых варианта;
первый минимально меняет намерение. Нужен выбор игрока, автоматической подмены нет.
Подтверждённое исправление планируется без повторной проверки. Собственная ветка
ведёт к финалу и проходит общую проверку событий сегмента.
Проверка допустимости действия при подтверждении не повторяется.
Содержательной модерации, редактора прозы и сжатия истории нет.

Проверяющая модель возвращает только точные замены `event_index/path/old/new`.
Индексы с нуля, путь через точку; пустой путь заменяет целое событие.
Python применяет все замены атомарно без дополнительного запроса. Сохраняется
число событий. Ошибочный адрес, несовпадение old или пересечение правок
не меняют черновик. При техническом сбое проверки допускаются две попытки,
затем показывается ошибка с возможностью повтора. Итоговые события сохраняются
перед написанием прозы: повтор после её сбоя не оплачивает проверку заново.
У финального сегмента проверяется разрешение главного конфликта; победа не обязательна.
Проверка ищет грубые нарушения выбора игрока, непрерывности ключевых состояний
и причинности главного конфликта. Стиль и мелкие детали не редактируются.
HTTP-журнал помечает этап как `review_segment_events`; диагностический JSONL
содержит `segment_review` с исходным сегментом, заменами и исправленным результатом.

Нечеловеческие персонажи обозначаются `kind=nonhuman` и получают существующую
сферу-заглушку; человеческий спрайт им не назначается. Старые сцены не переписываются.
Проза сохраняет существенные действия событий и не раскрывает последующие открытия
раньше времени. Переходы локаций принимает движок из событий, без цитаты из прозы.
Проза v2/v3 получает готовые события без общей адаптивной заготовки сюжета;
промпт требует одну сцену на событие. Говорящие из каста используют собственный ID,
слова эпизодических участников вне каста передаются косвенной речью с указанием источника.

Сетевой сбой прозы оставляет оплаченные события для повторной попытки.
Сбой генерации отложенной ветки не заменяет её необратимым техническим финалом.
Повтор своего действия после сбоя прозы использует уже оплаченный план.
Стартовая генерация событий после исчерпания повторов может закончиться
техническим сообщением вместо сюжета; художественное качество модель не гарантирует.

## Память, кеш и сохранения

Память — полный журнал сырых событий выбранного пути и решений игрока.
Числа/сроки находятся прямо в действиях; отдельных `facts`/`numbers`, сжатия,
обрезки и прошлой прозы в последующих промптах нет. Чужие и будущие ветки
не становятся произошедшими фактами.

Журнал — единственный источник сюжетной памяти. Дельты предметов, ресурсов,
правил мира и сюжетных нитей остаются внутри исходных событий; отдельные
реестры больше не пересчитываются и не сохраняются. Локальное состояние
локаций, погоды и спрайтов нужно для отображения, решения — для журнала игрока.

Порядок контекста: стабильные правила/каст/исходные условия → растущий журнал →
изменчивое задание. Кеш DeepSeek автоматический, совпадение не гарантируется.
Общий системный префикс одинаков на этапах событий, проверки и прозы.
Каталог фонов и творческие инструкции планировщика идут после журнала только
в запросах планирования; проза и проверка их не получают. Полный журнал не сокращается.
При cache miss инструкции всё равно отправлены полностью. API usage содержит
попадания/промахи; лимит контекста по-прежнему действует.

Снимки — `%USERPROFILE%/.story_engine/sessions` (до 40 последних файлов).
Последняя история предлагается при открытии игры, в том числе после перезапуска
сервера. Уже написанное можно читать без ключа и повторной оплаты генерации.
Новые клиенты передают ID исходной сцены: устаревший клик из другой вкладки
не перелистывает следующую сцену. Недоступность browser storage не ломает игру.

Диагностический `<session>_debug.jsonl` восстанавливает дерево и написанные сцены
через «Загрузить историю из файла». Можно начать с начала или развилки.
Файл `<session>_transcript.jsonl` содержит только показанный текст и для этого
не подходит. Логи по умолчанию пишутся на Desktop; папку/файл можно указать перед
стартом. В финале доступен экспорт текста в Markdown. Старые сохранения и форматы
событий читаются. Старые реестры без `event_history` сохраняются как исходный
контекст журнала, без восстановления удалённых механизмов. Неиспользуемые
настройки модели/модерации и флаги «спящих» персонажей игнорируются.
Ранее утраченное сжатием не восстанавливается.

## Графика и звук

80 дневных локаций и нейтральная заглушка. Игровые WebP — `backend/backgrounds`,
исходные дневные PNG/JSON — `assets/backgrounds/originals`.
Утро/вечер/ночь и погодные оттенки вычисляются в браузере. Масштабирование —
сглаженный ресэмплинг Canvas, без нейросети на ПК игрока.

Фон закреплён за ID места. Перемещение требует показанного перехода.
DeepSeek выбирает ID фона из компактного каталога при планировании события
(`location.background_id`); если места нет — `abstract_space`. Локального
сопоставления по словам больше нет. Сохранённый ID остаётся закреплён за местом;
старые сцены без ID используют заглушку без нового платного запроса.
DeepSeek задаёт время, погоду и эффекты; локальные правила проверяют их применимость
к фону, сезону, климату и источнику. Игра сама случайные эффекты не назначает.
Закрытые шахты, космос и заглушка имеют фиксированное освещение.
Неопознанные места записываются в журнал фонов, доступный через
`/visual/missing-backgrounds` и `/visual/missing-backgrounds/export`.

235 спрайтов — `assets/characters/cutouts`; оригиналы и разметка лиц сохранены.
Спрайт назначается на ID персонажа с сохранённым seed, без повторов внутри каста,
с учётом пола и крупных групп одежды. Неизвестный пол не угадывается.
При несовместимой/недостающей фигуре или сбое загрузки показывается прозрачная
гуашевая сфера, которую браузер рисует и тонирует динамически. Подробные признаки задания не равны проверенной
разметке каждого рисунка. Runtime-каталог — `backend/character_data/catalog.json`.

Эмоции `base`, `smile`, `tension` задаются событиями и меняются алгоритмической
деформацией лица. Дополнительные PNG не создаются. Палитра спрайтов совпадает
с фоном; диалог, выборы и звуковые панели используют тему времени суток.
Появление/уход — 450 мс; при reduced-motion — короткое растворение 180 мс.
Палитра меняется за 2.4 с, мимика — за 350 мс; reduced-motion отключает эти переходы.

Музыка — 17 инструментальных треков ccMixter, скачиваемых по необходимости.
Свой музыкальный ключ/хостинг не нужен. CC BY 3.0 допускает коммерческое
использование при соблюдении условий, включая атрибуцию. Авторы и сэмплы доступны
в игре по «Музыка и лицензии» и в `backend/music_catalogs/CREDITS.html`.
Кеш — `%USERPROFILE%/.story_engine/cache/music` или `STORY_ENGINE_MUSIC_CACHE`.
Все треки занимают около 101 MB; проверенный кеш работает без сети.
Сбой скачивания не блокирует сюжет. Подбор — локальная эвристика; бесшовные петли
не гарантируются. Дождь/гроза — отдельные локальные CC0 Ogg; источники и лицензии
в `backend/ambience/`. Звук и музыка по умолчанию выключены.

## Инструменты и проверки

`StoryEngine_Anima_Characters_Colab.ipynb` создаёт до 240 одетых взрослых образов
с личной папкой Google Drive. Рассчитан на Colab около 11 GB VRAM / 12 GB RAM;
Anima/ComfyUI не входят в игру. Для текущих 235 готовых спрайтов запускать его не нужно.

`CHARACTER_APPEARANCE_POOL.md` описывает локальные признаки и веса разнообразия.
После изменения пула: `python backend/sync_character_appearance.py`.
Для рабочих метаданных спрайтов: `python tools/build_runtime_character_catalog.py`.
Галереи `assets/characters/gallery.html` и `face_gallery.html` помогают проверять
исходники и разметку новых рисунков. Нужные офлайн-инструменты используют Pillow/NumPy;
игровой сервер их не импортирует.

```powershell
python -m unittest discover -s backend/tests -v
npm --prefix frontend test
npm --prefix frontend run build
```

Тесты используют подставные ответы, включая полное прохождение через HTTP API;
платных запросов не делают. Сборка Windows после сборки интерфейса:

```powershell
python -m pip install -r requirements-build.txt
cd backend
python -m PyInstaller --distpath ../dist run.spec
```

Результат — `dist/StoryEngine.exe` в корне проекта. Внутри интерфейс, WebP, рабочие PNG,
каталоги и эмбиент. Исходные рисунки, Colab, тесты и веса модели не включаются.
Для автоматической проверки запуска есть `STORY_ENGINE_NO_BROWSER=1` и
`STORY_ENGINE_PORT=0` (выбрать свободный порт).

## Журнал DeepSeek

Все обращения записываются в `logs/deepseek/deepseek_YYYY-MM-DD.jsonl` рядом
с проектом или exe.
`request`, `response`, `error` связаны по `request_id`. `generation_id` объединяет
повторы логической операции, `attempt` начинается с 1. Записываются промпты,
ответы, ошибки, длительность и токены, включая cache hit/miss. Ключ маскируется.
Сбой логирования не повторяет API-запрос. Эти журналы содержат историю и ввод
игрока, хранятся локально и не предназначены для импорта вместо `_debug.jsonl`.

## Если не загружаются завязки

Меню показывает причину сбоя и кнопку «Повторить загрузку завязок». Можно
ввести собственную завязку. Повтор выполняется только по нажатию кнопки.
Для проверки сетевых зависимостей Windows-сборки выполните
`dist\StoryEngine.exe --check-runtime`: ожидается `HTTPS runtime OK`.
Проверка не подключается к интернету и не использует API-ключ.


### Контекст прозы

Проза получает только события текущего сегмента, жанр/тон и стабильный справочник
персонажей. Полный журнал остаётся у планирования и проверки, в прозу он не передаётся.
Общий замысел и скрытые цели персонажей в запрос прозы также не входят.


## Экономия промптов (23 октября 2026)

- Неизменные правила прозы, формат blocks и запрет повторять метаданные находятся
  в системном префиксе рядом со стабильным справочником. Меняющиеся выбор/финал
  и события — в пользовательской части. В одном запросе правила не дублируются.
- Планирование и проверка сохраняют общий префикс: каст/канон, затем полный
  дополняемый исходный журнал; каталог и динамические задания идут после журнала.
  Проза получает только текущий сегмент и справочник с признаком ГГ.
- Уточняющие вопросы сокращены до рабочих правил; из инструкции общего плана
  убраны объяснения причин самих инструкций. Состав запросов не увеличен.
- Для ключевых действий результат и оставшееся ограничение описываются прямо
  в событии; части предмета различаются. Наблюдение отделяется от версии персонажа.
  Не вводить новые правила мира только ради разрешения конфликта.
- В справочнике планирования явно указаны пол и признак ГГ, даже если описание
  назначенного спрайта обезличено. Постоянство префикса сохраняется при чтении сцен.
- Удалён неиспользуемый _as_bool; исправлено устаревшее описание контекста прозы.
  Чтение старых сохранений и продолжение старых текстовых планов сохранены.
- Совпадение префикса даёт возможность кеширования, не гарантирует попадание.
  Процент экономии в рублях определяется реальными usage/cache_hit/cache_miss;
  локальная проверка длины текста не является измерением токенов или цены.
