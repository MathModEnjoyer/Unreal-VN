# Непрерывность локаций

DeepSeek выбирает место при планировании событий: `location: {id, label, background_id, transition?}`. Дополнительного запроса для выбора места или картинки нет. Проза описывает переход, не возвращая `transition_evidence`; сервер формирует у принятой сцены `location_id` и `location_transition`. Идентификатор принадлежит конкретному месту истории, например `anna_room`, а не универсальному изображению `bedroom`.

- Начальное место принимается свободно. Название `location` должно описывать помещение или окружение достаточно конкретно для подбора фона.
- До фактического перемещения ID и каноничное название остаются прежними. Новая реплика, обсуждение другого места, воспоминание, изменение погоды или времени суток переходом не считаются.
- Для перемещения событие задаёт `location.transition: "move"`; явная смена сцены/времени — `"cut"`. Сервер принимает переход из связанного v2/v3-события и формирует `location_transition: {"kind":"move"}`. Цитата из прозы не требуется. Без move/cut движок сохраняет прежнее место и отмечает `location_issue`.
- Промпт событий ограничивает бессмысленные перемещения: смена реплики и упоминание другой комнаты не меняют локацию. Проверка сегмента видит последовательность событий целиком и может исправить переходы до прозы. Отдельного запроса проверки перемещения нет.
- Только старые текстовые планы без структурного события используют прежний контракт цитаты. Уже написанные сцены не регенерируются.
- Реестр `StoryState.locations` хранит постоянный ID, каноничное имя и выбранный сервером `background_id`. При возвращении используются прежние имя и изображение, даже если модель описала место иначе. Точные повторения названия также объединяются при ошибочно выданном новом ID. Разные спальни нужно называть с уточнением владельца/здания и давать им разные ID.
- ID изображения выбирает модель из стабильного каталога в существующем запросе событий: `location.background_id`. Сервер проверяет ID/файл и закрепляет его за местом; произвольный путь не принимается. Локального поиска по словам больше нет. Погода/эффекты по-прежнему проверяются по фактическому фону.
- `abstract_space` — явная заглушка, если подходящего изображения нет. Неизвестный ID, пропущенный выбор фона в старом сохранении или недоступный файл дают заглушку без платных запросов. Сохранённый ID не подменяется случайным совпадением; при восстановлении файла он снова работает. Применение заглушек и технические сбои доступны в настройках и JSON-выгрузке.
- Реестр сохраняется в JSON-снимках и копиях веток. Перед материализацией сегмента контекст мест восстанавливается по его предкам в дереве, чтобы возврат к другой ветке не переносил туда места из уже просмотренной альтернативы.

Новые записи `segment_prose` в JSONL отмечены `location_schema: 1`, чтобы повторное воспроизведение сохраняло строгие правила даже при пропущенных моделью полях. После применения сегмента запись `segment_prose_final` сохраняет полученную прозу, ID и закреплённые фоны; при восстановлении она имеет приоритет над исходным ответом модели. Старые JSONL воспроизводят прежние явные названия без требования новых метаданных; старые JSON-снимки получают ID для известного текущего места. Уже сохранённая проза не переписывается.

Реализация: `scene_locations.py`, применение в `DeepSeekClient.apply_scene_to_state`, сохранение принятых полей в узлах дерева, закрепление через `VisualCatalog.recommend(background_id=...)`. Отдельные тесты: `tests/test_scene_locations.py`.
