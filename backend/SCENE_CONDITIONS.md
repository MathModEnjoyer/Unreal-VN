# Время и погода как состояние истории

В существующем запросе плана DeepSeek выбирает `initial_conditions`: время суток, наружную погоду и её интенсивность, сезон, температуру, климат и влажность. Затравка и уточнения игрока имеют приоритет. Правдоподобный случайный выбор делает модель один раз; в игре нет собственного случайного выбора погоды и нет отдельного запроса для её определения.

Начальные условия попадают в `StoryState.scene_conditions` перед построением дерева. Планировщик видит их в стабильном каноне и учитывает последующие изменения из журнала событий. Проза получает условия из событий посещаемого сегмента. Они не пересчитываются по часам компьютера, количеству реплик или номеру сцены.

В событии без изменений `conditions_change` пропускается. Если обстановка действительно изменилась, планировщик отправляет только дельту:

```json
{
  "conditions_change": {
    "time_of_day": "evening",
    "atmosphere": {"weather": "rain", "intensity": 0.6}
  }
}
```

Неуказанные и некорректные поля сохраняют прежние значения. Для окончания дождя требуется явно передать `{"atmosphere":{"weather":"clear"}}` внутри `conditions_change`; интенсивность при этом становится нулевой, если другое значение не задано. Изменение только времени суток сохраняет погоду, сезон и остальные условия. Изменение только силы дождя сохраняет время суток.

Смена места сама по себе не меняет погоду. В помещении осадки скрывает существующая политика фона; наружный дождь остаётся в состоянии и снова виден после возвращения на улицу. Шахты, космос, неподходящие снегу рисунки и остальные ограничения по-прежнему проверяются отдельно. Плавные переходы палитры используют новые разрешённые условия.

Локальные частицы (`ambient`, `ambient_source`, `ambient_intensity`) задаются в верхнем `atmosphere` события только для текущей сцены. Без повторного запроса не наследуются пепел, искры, угольки, светлячки или пыль. Одноразовые вспышки `screen_events` также не наследуются. Предыдущий локальный запрос может оставаться в контексте модели как напоминание, но не включает эффект в следующей сцене автоматически.

Сервер разворачивает компактную дельту в полные `time_of_day` и `atmosphere` для каждой принятой сцены. Поэтому интерфейс, сохранённые узлы дерева и журнал получают самостоятельную сцену с готовым состоянием, даже если событие не содержит `conditions_change`. Проза не дублирует погоду/эффекты: сервер берёт их из события. Редактор связности удалён: дельты применяются локально без отдельного запроса и сверки с повествованием.

JSON-снимки сохраняют актуальные условия. Перед генерацией другой ветки состояние восстанавливается от начальных условий по её собственным предкам, без переноса погоды из ранее просмотренной альтернативы. JSONL восстанавливается из плана и итоговых принятых сцен. Старые полные `time_of_day`/`atmosphere` поддерживаются как явные обновления. Если старый план или сбой планирования не дали начальных условий, планировщик задаёт их один раз в первом новом событии через `conditions_change`; игра не выдумывает их самостоятельно.

Реализация: `scene_conditions.py`; применение в `DeepSeekClient.apply_scene_to_state`; начальная установка в `server.py`; контекст и загрузка в `state_machine.py`. Тесты: `tests/test_persistent_conditions.py`.
